# 网页采集配置管理工具

离线版采集配置管理工具，涵盖站点管理、抽取模板编排、代理池配置、限速策略、重试机制、增量采集与数据落盘规则，所有配置持久化到浏览器本地存储。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `scraper-config-studio:entries` 这一项，或调用 `resetModule(模块)`。

## 落盘任务升级迁移（v1 → v2）

旧版数据落盘升级时，存储配置（输出路径、文件格式、分区策略、保留天数）随历史分区一起
迁移。该能力是纯前端数据层里的一套确定性迁移引擎，入口在「数据落盘」页的迁移面板，
「数据分发」页读取同一次提交戳的清单。代码与状态：

```text
frontend/src/
├── data/migration/
│   ├── types.ts          迁移领域模型（旧/新索引、配置、状态机、锁）
│   ├── legacy-seed.ts    旧版磁盘分区与「按批次号单键」的旧索引（含 STOR-7 缺陷夹具）
│   ├── engine.ts         复合键重建索引、配置随迁、保留期、部署校验、回滚（纯函数）
│   ├── digest.ts         确定性摘要与保留期计算（浏览器/Node 结果一致）
│   └── migration-store.ts  迁移状态 localStorage 持久化（可注入内存存储用于测试）
├── api/migration-service.ts  编排：目录锁 → 重建 → 构建 → 部署 → 切版本 → 清单 → 释放锁
├── stores/migration.ts       页面共用的迁移状态封装
└── views/{storage,export}/   迁移面板与分发清单面板
```

关键规则（均有 `frontend/tests/migration.test.mjs` 用例覆盖，`npm test` 运行）：

- **批次索引问题定位**：旧索引以「批次号」为单键，同批次多分区互相覆盖丢条目
  （STOR-7 的 `B20261113` 两个 CSV 分区只剩一个）。新版上线前回到磁盘分区清单，按
  复合键 `(批次号, 分区路径)` 重建，补回丢失分区且不产生重复键。
- **配置随迁**：输出路径、文件格式、分区策略、保留天数逐项随历史分区迁移，任一漂移即构建失败。
- **门控切换**：阶段严格按 `INDEX_REBUILT → BUILT → DEPLOYED → SWITCHED` 推进，
  只有完整构建并部署成功后写入版本才从 v1 切到 v2；任一阶段失败自动回滚、保持 v1。
- **同目录并发**：提交锁按目录（配置编号）隔离，同一目录第二个提交被拒绝、只有一个完成，
  不同目录互不阻塞；结束（成功/失败）释放本目录锁。
- **同提交戳**：数据分发清单不另生成戳，读取迁移侧最近一次提交戳，路径与摘要与迁移结果一致。
- **保留期**：到期时刻 = 旧批次结束时间 + 保留天数，迁移不重置起算点；保留期内旧分区受保护，
  新规则不能提前删除。STOR-7 为 11 月 13 日 08:10 + 14 天 = 11 月 27 日 08:10。
- **回滚**：恢复旧索引与已启用配置、写入版本回到 v1；迁移不修改任何分区摘要。
- **STOR-7**：旧 CSV 分区从 `/collect/a` 迁到 `/archive/b`，保留 14 天，迁移前后摘要逐条一致。

测试用 Node 自带的 TS 类型剥离运行（无需额外依赖），通过 `tests/alias-register.mjs`
把 `@/` 别名解析到 `src/`，与 vite 浏览器侧加载同一份源码。
